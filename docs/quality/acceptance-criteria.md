## Acceptance Criteria

| Criteria ID | Related Requirement | Related Feature | Criteria | How To Verify | Status |
|---|---|---|---|---|---|
| QA-AC-001 | REQ-001 | FEAT-003 | Руководитель с правом `view` на дашборд видит показатели подразделения за сегодня, текущую неделю и текущий месяц, динамику и отставание от нормы | Войти как руководитель → открыть главный дашборд → проверить наличие всех периодов и метрик из подключённых источников | draft |
| QA-AC-002 | REQ-002 | FEAT-003 | Руководитель выбирает подразделение или сотрудника и видит те же метрики в выбранном разрезе; объекты вне scope недоступны | Выбрать подразделение → проверить метрики; выбрать сотрудника → проверить метрики; попытаться открыть объект вне scope → доступ запрещён | draft |
| QA-AC-003 | REQ-003 | FEAT-003 | На дашборде отображается AI-сводка (просадки, зоны внимания, кого контролировать/похвалить) при достаточных данных; без данных — только числовые метрики | Сценарий с полными данными → AI-сводка видна; сценарий без данных для AI → сводка скрыта, числовые метрики на месте | draft |
| QA-AC-004 | REQ-004 | FEAT-003 | Вкладка «Клиенты к разбору» показывает список клиентов с обоснованием только в scope руководителя | Открыть вкладку → проверить список и обоснования; убедиться, что клиенты вне scope не отображаются | draft |
| QA-AC-005 | REQ-005 | FEAT-004 | Руководитель с `edit` создаёт разбор с комментарием и задачами; запись фильтруется; задачи появляются у сотрудника; статус задач обновляется в истории | FLOW-002: создать разбор → проверить запись в истории → войти как сотрудник → задачи на дашборде → обновить статус → проверить в истории | passed |
| QA-AC-006 | REQ-006 | FEAT-004 | Сотрудник видит только свои показатели (качество, динамика, отставание от плана) и задачи от руководителя | Войти как сотрудник → проверить личный дашборд → убедиться, что чужие данные недоступны | passed |
| QA-AC-007 | REQ-007 | FEAT-005 | AI-аналитика формирует стандартный отчёт и канвас по качеству и динамике для сотрудника или подразделения при наличии транскрипций и критериев | FLOW-003: запустить стандартный отчёт → проверить канвас, метрики качества, рекомендации к разбору | passed |
| QA-AC-008 | REQ-008 | FEAT-005 | При `edit` руководитель добавляет/редактирует/удаляет критерии; при `view` — только чтение; новые критерии используются в AI-аналитике | Изменить критерий → запустить AI-отчёт → проверить, что оценка учитывает новый критерий; проверить режим view | passed |
| QA-AC-009 | REQ-009 | FEAT-007 | Руководитель описывает кастомный отчёт простым языком; система сохраняет его и позволяет повторный запуск в AI-аналитике | FLOW-004: создать кастомный отчёт → сохранить → запустить из AI-аналитики → результат соответствует описанию | passed |
| QA-AC-010 | REQ-010 | FEAT-006 | База знаний наполняется через интерфейс; материалы доступны по правам; изменения влияют на ответы AI-агентов | Добавить материал → задать вопрос AI-агенту по этому материалу → ответ использует добавленное; проверить ограничение по правам | passed |
| QA-AC-011 | REQ-011 | FEAT-006 | Руководитель с `use` ведёт диалог с AI-агентом; ответ опирается на RAG и контекст клиента (комментарий, записи) | FLOW-005: задать вопрос по клиенту с контекстом → проверить релевантность ответа; проверить недоступность без права `use` | passed |
| QA-AC-012 | REQ-012 | FEAT-006 | Сотрудник с `use` получает помощь по продукту/отработкам/клиенту в рамках выданных прав; при недоступном материале — явное сообщение | FLOW-007: задать вопрос → проверить ответ; запросить материал вне прав → агент сообщает об ограничении | passed |
| QA-AC-013 | REQ-013 | FEAT-001 | Руководитель с `edit` назначает сотруднику права на модули и разделы RAG; попытка выдать право шире потолка блокируется | Назначить права в пределах потолка → успех; попытаться выдать `edit` при своём `view` → блокировка с сообщением | passed |
| QA-AC-014 | REQ-014 | FEAT-001 | Многоуровневая иерархия руководителей работает; нижестоящий не может дать сотруднику больше прав, чем у него самого | Настроить двух руководителей с разными правами → нижестоящий пытается расширить права сотрудника → система блокирует | passed |
| QA-AC-015 | REQ-015 | FEAT-002 | Показатели агрегируются из CRM, телефонии и отчётности; недоступный источник явно помечен | Подключить источники → проверить метрики на дашборде; отключить один источник → проверить пометку/пустое состояние | draft |
| QA-AC-016 | REQ-016 | FEAT-002 | Записи принимаются из телефонии и ручной загрузки; транскрипции создаются и доступны для AI-аналитики | Загрузить запись / получить из телефонии → проверить транскрипцию → использовать в AI-отчёте | draft |
| QA-AC-NFR-001 | REQ-NFR-001 | FEAT-001 | Данные сотрудника видны ему и руководителям только в scope; изменения прав фиксируются в аудите | Проверить доступ внутри/вне scope; изменить права → проверить audit log | draft |
| QA-AC-NFR-002 | REQ-NFR-002 | FEAT-002 | Блок «сегодня» отражает актуальные данные на момент открытия дашборда | Обновить данные в источнике → обновить дашборд → метрики «сегодня» изменились | draft |
| QA-AC-NFR-003 | REQ-NFR-003 | FEAT-002 | При недоступности интеграции — явное пустое/частичное состояние с причиной; частичный сбой телефонии не скрывает другие метрики | Симулировать недоступность CRM / телефонии → проверить UI-состояния и пометки неполных данных | draft |
| QA-AC-NFR-004 | REQ-NFR-004 | FEAT-001 | Модули без прав скрыты или недоступны с понятным сообщением; AI-агент сообщает об ограничении контекста | Войти с ограниченными правами → проверить недоступные модули; запросить недоступный материал в агенте → явное сообщение | draft |
