# Demo Scenario 1 — First Working Demo

> Сквозной сценарий первого рабочего демо MVP. Используется для разработки, QA и презентации.

← [README.md](../../../README.md) · [mvp-scope.md](./mvp-scope.md) · [acceptance-criteria.md](../../mvp/acceptance-criteria.md) · [product-glossary.md](../../../product-glossary.md)

## Цель демо

Показать полный цикл: **настройка workspace → загрузка звонка → AI-разбор → карточка сотрудника с зонами роста.**

Длительность демо: **~15–20 минут** (с учётом ожидания AI-анализа).

---

## Предусловия

- Приложение развёрнуто (local / staging)
- AI-провайдер подключён и работает
- Подготовлены тестовые данные (см. [Test Data](#test-data) ниже)

---

## Шаги

### 1. Админ создаёт Workspace

| | |
|---|---|
| **Действие** | Регистрация / вход → «Создать workspace» → название компании |
| **Input** | Название: `Demo Sales Co` |
| **Expected** | Workspace создан, пользователь — Admin |
| **Screen** | Workspace setup / onboarding |

---

### 2. Создаёт Pipeline из 3 этапов

| | |
|---|---|
| **Действие** | Pipeline Builder → добавить 3 stage |
| **Input** | См. таблицу ниже |
| **Expected** | Pipeline сохранён, stages отображаются в UI |

| Stage | Touchpoint types | Описание |
|-------|------------------|----------|
| **Первый контакт** | call, message | Первый звонок / сообщение лиду |
| **Квалификация** | call | Уточнение потребности, бюджета, сроков |
| **Назначение встречи** | call | Закрытие на следующий шаг — встречу / демо |

---

### 3. Добавляет 5 критериев оценки звонка

| | |
|---|---|
| **Действие** | Quality Criteria → создать 5 criteria, привязать к stage «Первый контакт», type = call |
| **Expected** | 5 criteria сохранены и видны в списке stage |

| # | Criterion | Описание |
|---|-----------|----------|
| 1 | **Приветствие и представление** | Менеджер представился, назвал компанию, обозначил цель звонка |
| 2 | **Выявление потребности** | Задал ≥2 открытых вопроса о ситуации клиента |
| 3 | **Работа с возражениями** | При возражении — не спорит, уточняет, отвечает по скрипту |
| 4 | **Презентация ценности** | Связал продукт с озвученной потребностью клиента |
| 5 | **Закрытие на следующий шаг** | Предложил конкретный next step с датой / временем |

---

### 4. Загружает базу знаний

| | |
|---|---|

| **Input** | Минимум 2 документа (см. Test Data) |

| | |

| Поле | Значение |
|------|----------|

---

### 7. Получает AI-разбор

| | |
|---|---|
| **Действие** | Ожидание processing → открыть Evaluation Detail |
| **Expected** | Evaluation содержит все обязательные поля |

**Checklist результата:**

| Поле | Есть | Пример содержания |
|------|------|-------------------|
| score | ☐ | 72/100 |
| summary | ☐ | «Менеджер представился, но не задал уточняющих вопросов о бюджете…» |
| strengths | ☐ | ≥1 пункт с привязкой к criterion |
| weaknesses | ☐ | ≥1 пункт с привязкой к criterion |
| recommendations | ☐ | ≥1 конкретное действие |

---

### 8. Видит карточку сотрудника с зонами роста

| | |
|---|---|
| **Действие** | Employees → Алексей Петров → Employee Profile |
| **Expected** | Профиль содержит evaluation из шага 7 + growth zones |

**Checklist Employee Profile:**

| Элемент | Есть |
|---------|------|
| История evaluations (≥1 запись) | ☐ |
| Score последней evaluation | ☐ |
| Growth zones (≥1 после повторного upload*) | ☐ |
| Ссылка на Evaluation Detail | ☐ |

\* Для демо growth zones на одном звонке: показать weaknesses как preliminary zones. Полноценная агрегация — после 2+ evaluations (AC-12).

## Критерий успеха демо

Демо считается успешным, если зритель (или QA) проходит шаги 1–8 **без помощи разработчика** и видит:

1. Настроенный pipeline с 3 stages и 5 criteria
2. AI-разбор загруженного звонка с score и рекомендациями
3. Employee Profile с историей и зонами роста
4. Manager Card со списком сотрудников и последней оценкой

---

## Known limitations (ожидаемо в MVP)

- Один workspace, один admin
- Growth zones полноценно работают после ≥2 evaluations
- Нет real-time processing indicator (достаточно polling / refresh)
- CSV сделок — опционально, не блокирует демо
