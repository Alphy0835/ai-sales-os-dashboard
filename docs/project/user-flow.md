## Flow: FLOW-001 — Обзор подразделения

### Actor

Руководитель

### Goal

Быстро понять состояние подразделения и решить, кого и что разбирать, без ручного прослушивания всех звонков.

### Preconditions

- Пользователь авторизован на User Level.
- Подключены источники данных: CRM, телефония, отчётность.
- Руководителю выдан scope на подразделение.

### Main Scenario

1. Руководитель входит в систему и попадает на главный дашборд.
2. Видит агрегированные данные подразделения из CRM, телефонии и таблиц отчётности.
3. Смотрит блоки: сегодня, текущая неделя, текущий месяц, динамика, отставание от нормы.
4. Читает AI-сводку: просадки, сотрудники под контроль, сотрудники к похвале.
5. При необходимости выбирает подразделение или конкретного сотрудника и видит те же метрики в выбранном разрезе.
6. Переходит во вкладку «Клиенты к разбору» и смотрит список клиентов с обоснованием.

### Result

Руководитель понимает, где проблема, кого разбирать и с какими клиентами работать в первую очередь.

### Alternative Scenarios

- Если у руководителя несколько подразделений, он сначала выбирает scope, затем детализирует до сотрудника.
- Если AI-сводка недоступна из-за нехватки данных, дашборд показывает только числовые метрики.

### Error / Edge Cases

- Нет данных из интеграции → показывается пустое состояние с указанием источника, который не отдал данные.
- Нет прав на подразделение → доступ запрещён.
- Частично недоступна телефония → метрики качества общения помечаются как неполные.

## Flow: FLOW-002 — Разбор с сотрудником

### Actor

Руководитель

### Goal

Провести разбор, зафиксировать договорённости и поставить задачи сотруднику.

### Preconditions

- Выполнен или частично выполнен FLOW-001.
- У руководителя есть право `edit` на модуль «История разборов».

### Main Scenario

1. Руководитель открывает вкладку «История разборов».
2. Создаёт новую запись: выбирает сотрудника, указывает дату.
3. Заполняет комментарий по сотруднику и описание обсуждения.
4. Добавляет одну или несколько задач сотруднику.
5. Сохраняет запись.
6. Система показывает задачи в личном дашборде сотрудника (FLOW-006).

### Result

Разбор зафиксирован, задачи поставлены и видны сотруднику.

### Alternative Scenarios

- Руководитель фильтрует историю по подразделению или сотруднику и дополняет прошлый разбор статусом выполнения задач.
- Разбор начинается из карточки клиента во вкладке «Клиенты к разбору».

### Error / Edge Cases

- Только `view` на историю разборов → создание и редактирование недоступны.
- Сотрудник вне scope руководителя → выбор недоступен.

### Related Docs

- `docs/project/user-roles.md` — делегирование задач
- FLOW-006

## Flow: FLOW-003 — AI-аналитика

### Actor

Руководитель

### Goal

Получить AI-отчёт по качеству общения и динамике по сотруднику или подразделению.

### Preconditions

- Есть записи общений и транскрипции из телефонии или ручной загрузки.
- Настроены критерии оценки качества.
- У руководителя есть право `view` или `run` на AI-аналитику.

### Main Scenario

1. Руководитель открывает вкладку «AI-аналитика».
2. Выбирает объект: сотрудник или подразделение.
3. Запускает стандартный шаблон отчёта или формирует кастомный запрос.
4. Получает канвас с метриками качества по этапам, динамикой улучшений и просадок.
5. Видит рекомендации: что проработать с сотрудником и что вынести на разбор.

### Result

Руководитель получает структурированную AI-аналитику для решения по сотруднику или подразделению.

### Alternative Scenarios

- Используется кастомный отчёт, описанный ранее в настройках системы.
- Отчёт сохраняется и используется как контекст перед FLOW-002.

### Error / Edge Cases

- Нет транскрипций → отчёт по качеству недоступен, показывается причина.
- Недостаточно данных для динамики → отчёт строится только по текущему периоду.

### Related Docs

- `project-idea.md` — AI-аналитика и канвасы
- `docs/project/terminology.md` — Критерий оценки, Канвас, Транскрипция

## Flow: FLOW-004 — Настройка системы

### Actor

Руководитель

### Goal

Настроить критерии, отчёты, базу знаний и права сотрудников в рамках своих полномочий.

### Preconditions

- У руководителя есть право `view` или `edit` на модуль «Настройки системы».
- Для выдачи прав сотрудникам у руководителя должно быть право `edit` на управление доступами.

### Main Scenario

1. Руководитель открывает вкладку «Настройки системы».
2. При наличии `edit` настраивает критерии оценки: добавляет, удаляет, редактирует описания.
3. Описывает кастомные отчёты простым языком; система структурирует промпт для AI-агентов.
4. Наполняет базу знаний: продукты, отработки, инфоповоды и другие материалы.
5. Выдаёт сотрудникам права на модули и материалы, не превышая свой потолок прав.
6. Сохраняет изменения.

### Result

Система работает по актуальным правилам оценки, отчётности, знаниям и правам команды.

### Alternative Scenarios

- При `view` руководитель только просматривает критерии и базу знаний без редактирования.
- Вышестоящий руководитель заранее ограничил набор доступных модулей.

### Error / Edge Cases

- Попытка выдать сотруднику право шире своего → система блокирует действие.
- Изменение критериев без `edit` → режим только чтения.

## Flow: FLOW-005 — AI-агент руководителя

### Actor

Руководитель

### Goal

Обсудить с AI стратегию закрытия клиента, скрипты и тактику работы с опорой на знания компании.

### Preconditions

- У руководителя есть право `use` на AI-агент.
- База знаний наполнена в доступном scope.
- При необходимости выбран контекст клиента, комментарий или записи общения.

### Main Scenario

1. Руководитель открывает вкладку «AI-агент».
2. Формулирует запрос: стратегия закрытия, проработка скрипта, разбор сложного кейса.
3. При необходимости прикладывает контекст клиента и записи общения.
4. Получает ответ с опорой на RAG-базу бизнеса и примеры успешных/неуспешных сделок.
5. Использует результат на разборе или в работе с командой.

### Result

Руководитель получает прикладные рекомендации в контексте специфики бизнеса.

### Alternative Scenarios

- Запрос строится на основе клиента из вкладки «Клиенты к разбору».
- Ответ агента используется как материал для FLOW-002.

### Error / Edge Cases

- Нет доступа к нужному разделу базы знаний → агент сообщает об ограничении контекста.
- Нет права `use` → вкладка недоступна.

### Related Docs

## Flow: FLOW-006 — Личный дашборд

### Actor

Сотрудник

### Goal

Увидеть своё текущее состояние, динамику и задачи от руководителя.

### Preconditions

- Пользователь авторизован как сотрудник.
- Подключены источники данных по его активности.

### Main Scenario

1. Сотрудник входит в систему и попадает на личный дашборд.
2. Видит свои показатели: качество касаний, динамику, отставание от плана.
3. Смотрит блок задач, поставленных руководителем.
4. При необходимости открывает детали задачи и отмечает прогресс, если это предусмотрено процессом.

### Result

Сотрудник понимает, где просадка, какие задачи нужно выполнить и на что обратить внимание.

### Alternative Scenarios

- Набор метрик на дашборде сотрудника со временем может отличаться от руководительского, если так настроено правами.

### Error / Edge Cases

- Нет задач → блок задач показывает пустое состояние.
- Нет данных по активности → метрики недоступны с пояснением причины.

## Flow: FLOW-007 — AI-агент сотрудника

### Actor

Сотрудник

### Goal

Получить помощь по отработкам, продукту и работе с конкретным клиентом.

### Preconditions

- У сотрудника есть право `use` на AI-агент.
- Руководитель выдал доступ к нужным материалам базы знаний и сценариям.

### Main Scenario

1. Сотрудник открывает вкладку «AI-агент».
2. Задаёт вопрос по продукту, отработке или сложной ситуации с клиентом.
3. При необходимости добавляет комментарий о клиенте и ссылку/загрузку записи общения.
4. Получает рекомендации в рамках выданных прав и доступной RAG-базы.
5. Применяет рекомендации в работе с клиентом.

### Result

Сотрудник получает прикладную помощь без эскалации к руководителю по каждому вопросу.

### Alternative Scenarios

- Сотрудник использует агента для подготовки к разбору с руководителем.
- Доступен только частичный контекст базы знаний по решению руководителя.

### Error / Edge Cases

- Руководитель не выдал доступ к функции → вкладка недоступна.
- Запрошенный материал вне выданных прав → агент сообщает об ограничении.

### Related Docs

- `docs/project/user-roles.md` — правило потолка прав
- `docs/project/terminology.md` — RAG, AI-агент, База знаний
