## Integration Level

### ROLE-INT-001 — Интегратор

**Назначение:** установка системы, подключение интеграций, техническая настройка, контроль логов, ошибок и стабильности.

**Типовые права:**
- доступ к Integration Level;
- настройка CRM, телефонии, источников отчётности и записей общений;
- управление технической конфигурацией и окружениями;
- просмотр системных логов, ошибок и метрик стабильности.

**Как получает роль:** назначается командой внедрения или владельцем инсталляции на Integration Level.

**Статус:** детальная матрица прав и flow интегратора прорабатываются отдельно.

## User Level

### ROLE-USR-001 — Руководитель

**Назначение:** контроль работы подразделения, раннее выявление просадок, разборы с сотрудниками, настройка системы в рамках выданных прав.

**Область видимости:**
- своё подразделение;
- несколько подразделений — если выдан соответствующий scope;
- конкретные сотрудники внутри доступного scope.

**Модули и права:**

| Модуль | Что даёт | Возможные права |
|---|---|---|
| Дашборд | Сводка по подразделению, сотрудникам, динамике, отставанию от нормы, AI-сводка | view |
| Детализация | Те же метрики в разрезе сотрудника или подразделения | view |
| Клиенты к разбору | Список клиентов, требующих разбора, с обоснованием | view |
| История разборов | Фиксация разборов, комментариев, задач, фильтры | view / edit |
| AI-аналитика | Стандартные и кастомные отчёты, канвасы по качеству | view / run |
| Настройки системы | Критерии оценки, кастомные отчёты, база знаний, права сотрудников | view / edit |
| AI-агент | Диалог по стратегии, скриптам, клиентам с доступом к RAG | use |

**Как получает роль:** создаётся на User Level интегратором или вышестоящим руководителем с правом управления доступами.

### ROLE-USR-002 — Сотрудник

**Назначение:** работа со своими показателями, выполнение задач от руководителя, использование AI-ассистента в рамках выданных прав.

**Область видимости:** только свои данные, задачи и материалы, доступные по правам.

**Модули и права:**

| Модуль | Что даёт | Возможные права |
|---|---|---|
| Личный дашборд | Свои показатели, динамика, отставание от плана, задачи от руководителя | view |
| AI-агент | Отработки, информация по продукту, помощь по клиенту в рамках прав | use |

**Как получает роль:** создаётся руководителем или выдаётся через управление доступами в настройках системы.

## Permission Model

### Базовые режимы

| Режим | Смысл |
|---|---|
| none | Модуль недоступен |
| view | Только просмотр |
| edit | Просмотр и изменение |
| run | Запуск действия без редактирования настроек (например, AI-отчёт) |
| use | Использование функции (например, AI-агент) |

### Иерархия руководителей

Руководители могут быть многоуровневыми: вышестоящий задаёт scope и права нижестоящему.

Пример: если у руководителя только `view` на критерии оценки, он не может выдать сотруднику `edit` на этот модуль.

### Делегирование сотрудникам

Руководитель выдаёт сотрудникам права через модуль «Настройки системы → права доступа».

**Правило потолка:** сотрудник не может получить право шире, чем у руководителя, который его назначил.

| Если у руководителя | Сотрудник может получить |
|---|---|
| view на модуль | только view или none |
| edit на модуль | view или edit |
| use на AI-агент | use или none |
| none на модуль | none |

### Наследование материалов RAG

Доступ к материалам базы знаний и сценариям AI-агента также ограничен правами руководителя. Сотрудник видит только те разделы знаний и функции агента, которые разрешены его руководителем.

## Role Assignment

| Кто назначает | Кому | Где |
|---|---|---|
| Интегратор | Первого руководителя организации | Integration Level |
| Руководитель | Сотрудников и права сотрудников | User Level → Настройки системы |
| Вышестоящий руководитель | Нижестоящих руководителей и их scope | User Level → Настройки системы |
